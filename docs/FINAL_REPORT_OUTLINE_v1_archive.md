## v1 대비 v2에서 바뀐 점 요약
- 2장 구조: v1은 2.1(도메인지식)/2.2(LangGraph 기술배경) 둘로 나뉨 → v2는 2.1 하나로 합쳐지고 2.1.2로 축약됨. **LangGraph를 왜 이 계열 기술로 조사/채택했는지에 대한 별도 서술(v1 2.2)은 v2엔 없음** — 필요하면 아래서 복원.
- 3장 구조: v1은 3.1(구성도)/3.2(데이터준비)/3.3(데이터분석+파라미터+최적화)/3.4(QA롤백)/3.5(웹제어판) 5개 절 → v2는 3.1(아키텍처+스택)/3.2(탐지모델설계, 파라미터~최적화 전부 포함)/3.3(운영시스템, QA롤백+웹제어판 통합) 3개 절로 압축.
- 4장: v1은 4.6에 **멘토 피드백 반영을 표로 정리한 중앙집중식 색인 절**이 있었음(실제 대응 서술은 본문에, 4.6은 체크용 표) → v2는 이 표 자체를 없애고 본문 삽입(📌 표시)만 남김. **채점자가 "네 지적사항 다 대응했는지" 한눈에 보려면 이 표가 유용할 수 있으니, 필요하면 아래서 복원해서 5장이나 부록에 추가.**
- Grafana 대시보드가 v1은 4.4로 독립된 절 → v2는 3.3.2(관제시스템) 안에 폐합.

## (v1) 3.1 시스템 구성도 — 원래 세분화됐던 구조 (참고용)

v1은 지금 v2의 3.1~3.2에 걸쳐 있는 내용을 아래처럼 더 잘게 나눴었음:

- **3.1 시스템 구성도**: 전체 아키텍처 + 팀원별 역할 표시 + 노드별 정의표
  - **3.1.1 상태(State) 및 기술스택**: `PipelineState` 스키마 + 기술스택 선택근거표
  - **3.1.2 리소스/시나리오별 조치 매핑**: 표(리소스별 → 이상유형 → 조치) + WAF 연동 설명(Rate-based Rule vs IP블랙리스트)
  - **3.1.3 EC2 오버프로비저닝 탐지/조치 신규 구현**: Stop/Resize 분리 이유, 임계치 밴드 설계, 실측 결과 — *v2에서는 이 내용이 3.2.3(데이터분석및파라미터)으로 흡수됨*
- **3.2 데이터 준비**: (v2의 3.2.2와 거의 동일하게 이어짐)
- **3.3 데이터 분석 및 파라미터**:
  - 3.3.1 탐지 로직/하이퍼파라미터 선정 근거 (v2의 3.2.3과 동일)
  - 3.3.2 IsolationForest 학습데이터 구축/평가 + 오버피팅 논의 (v2의 3.2.4와 동일)
  - 3.3.3 최적화 (v2의 3.2.5와 동일)
- **3.4 QA 및 자동 롤백**: (v2의 3.3.1 후반부로 흡수됨)
- **3.5 웹 제어판**: (v2의 3.3.2로 흡수됨, 이때는 화이트리스트 UI 개선 전이라 그 내용은 없었음)
